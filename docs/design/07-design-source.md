# 07 — 设计源文件与同步流程

> 状态：首版 · 2026-11-16
> 作用：回答「设计稿在哪、谁说了算、怎么同步到代码」这三个问题
> 读者：设计师、前端实现者、评审者

## 1. 为什么要这份文件

Penpot 源文件保存在个人账号里，**不在 Git 仓库里**。如果只依赖 Penpot，半年后可能出现
「代码还在、设计打不开」或者「改过设计但没人知道改了什么」的情况。

因此约定：**Penpot 负责视觉，Git 负责契约**。仓库里的文件必须能在没有 Penpot 的情况下独立解释清楚：
页面长什么样、用了哪些值、有哪些组件、怎么验收。

## 2. 事实来源划分

| 内容 | 唯一事实来源 | 仓库中的对应物 |
|---|---|---|
| 页面结构、导航层级、用户流程 | `docs/design/01-ia.md` | 同名文件 |
| 视觉外观（布局、间距、颜色、圆角） | Penpot 画板 | `03-hifi/` 快照 + `04-tokens.md` |
| 颜色 / 字号 / 间距等具体数值 | `04-tokens.md` | 同名文件（CSS 变量） |
| 组件与状态 | `05-components.md` | 同名文件 |
| 验收标准 | `06-acceptance.md` | 同名文件 |
| 前端实现 | `frontend/src/` | 代码 |

冲突处理顺序：**01-ia（结构）→ 04/05/06（契约）→ Penpot（像素）**。
即：如果画板与文档不一致，先确认文档是不是要改；文档改完再改画板，不允许"以图为准"默默偏离 IA。

### 3.1 画板命名约定

- 一个页面一个画板，画板名 = `页面名 · 断点`，例如 `工作台 · 1440`。
- 状态变体用后缀：`工作台 · 侧边收起`。
- 画板右上角可以放一个 24px 的说明标签（可选），写明该画板对应的验收编号（如 `A-1`）。

## 4. 快照规范

目录：`docs/design/03-hifi/`，详见其中的 `README.md`。

- 格式：PNG，2 倍图（1440 画板导出 2880 宽；1200 宽画板导出 2400 宽）。
- 命名：`NN-<ascii-名称>.png`，如 `01-workbench-1440.png`；不要用中文做文件名（会让 guards 误报越界）。
- 现有文件：`01-workbench-1440.png`、`02-workbench-collapsed.png`、`03-components-1200.png`；供应商与切换流程快照待导出（`04-providers-1440.png`、`05-switch-preview-1440.png`、`06-switch-result-1440.png`、`07-switch-conflict-1440.png`、`08-import-select-1440.png`、`09-import-preview-1440.png`、`10-import-error-1440.png`、`11-chat-collapsed-1200.png`、`12-history-1440.png`）。文件名只用 ASCII，原因见该目录 README。
- 时机：每次画板定稿、或发生肉眼可见改动时更新，与文档同一次提交。
- 快照是**证据**不是**源**：只在 Penpot 不可用时用于对照，不用于量像素以外的用途。

## 5. 导出代码：只作标尺

Penpot 可以导出 HTML + CSS（插件 API `generateMarkup` / `generateStyle`，界面上是「导出代码」）。
实测输出特征：

- 结构是 `div` 套 `div`，类名是哈希（如 `f33e9872a983`）；
- 自动布局会正确转成 `display:flex` + `row-gap` + `padding`；
- 没有组件复用、没有事件、没有状态管理。

### 5.1 允许的用法

1. 对着导出结果量间距、圆角、阴影，核对 `04-tokens.md` 的值。
2. 复杂布局（如三段式 + 自动换行）拿不准时，参考它生成的 flex 参数。
3. 一次性静态页（营销页、说明页）可以直接用。

### 5.2 禁止的用法

- **不得**把导出的 HTML/CSS 直接复制进 `frontend/src/`：不可维护，且与 Vue 组件体系冲突。
- **不得**因为导出代码里是某个值，就绕过 `04-tokens.md` 在组件里写裸值。

### 5.3 正确的转换步骤

1. 按 `05-components.md` 的清单，把导出结构拆成组件（`ToolListItem`、`StatusBadge`…）。
2. 颜色/间距/圆角一律换成 `04-tokens.md` 的 CSS 变量。
3. 交互与状态按状态矩阵补：hover / focus / loading / error。
4. 用 `06-acceptance.md` 的清单验收，而不是"看起来差不多"。

## 6. 修改设计的流程

1. 先看 `01-ia.md`：这次改动是否影响信息结构？影响则先改 IA 并说明原因。
2. 在 Penpot 改画板。
3. 导出对应快照到 `03-hifi/`，覆盖同名文件。
4. 若数值变了，同步 `04-tokens.md`；若组件变了，同步 `05-components.md`。
5. 若验收方式变了，同步 `06-acceptance.md`。
6. 与文档同一次提交，提交信息用 `docs(design): ...`。

## 7. 已知限制

- Penpot 文件不在版本控制里，无法 diff；只能靠快照 + 文档描述变更。
- 令牌目前只存在于 Penpot 里，**没有导出成 JSON**；`04-tokens.md` 是手工维护的镜像，改令牌时两边都要改。
- 画板不含 hover / focus 态（见 `05-components.md` 状态矩阵中标「必」的格子），这些由实现卡补设计。
- 折叠态是**独立画板**，不是组件变体；改一处不会自动同步另一处。
- `组件总览 · 1200` 里的组件是**手工复制**的镜像，不是 Penpot 组件实例；改了主画板不会自动同步过去。
- 工具列表**不做搜索框**（ADR-014），画板与文档均已移除，后续实现不要自行加回。
