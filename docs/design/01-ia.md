# 01 — 信息架构

> 状态：示例基线，可按实际用户测试继续调整。
> 目标：先说明「用户要做什么、信息放在哪里、页面之间如何衔接」，不限定视觉风格。

## 1. 设计目标

CC-Roster 是本机 AI 编程工具的统一控制台。用户打开后应能快速回答：

1. 本机发现了哪些 AI 工具，各自配置是否正常？
2. 当前工具使用哪个供应商和模型？
3. 如何在确认影响后切换配置，并在出错时恢复？

信息架构优先服务于「查看工具 → 理解状态 → 决定下一步」；聊天是围绕工具与项目展开的工作区，不取代配置管理主线。

## 2. 核心对象与关系

| 对象 | 用户理解 | 关系 |
|---|---|---|
| 工具 | 已安装或被发现的 AI 编程工具，例如 Claude Code、Codex CLI | 一个工具对应一个稳定的列表条目 |
| 档案 | 可复用的供应商、接口地址、凭证引用和模型组合 | 一个档案可绑定多个工具；工具同一时刻使用一个当前档案 |
| 项目 | 用户选择的本地工作目录 | 会话归属于项目，并关联使用的工具 |
| 会话 | 与某个工具进行的一段对话或历史记录 | 属于项目；可继续、查看或只读回放 |
| 快照 | 配置变更前保存的可恢复状态 | 关联一次明确的配置应用操作 |
| 操作记录 | 用户可读的配置变更审计信息 | 记录操作时间、目标工具、字段变更和结果 |

产品规则：工具是主导航中的稳定对象；档案是工具可使用的配置资源；项目用于组织工作上下文。切换档案不改变工具的身份。

## 3. 全局导航

```text
应用
├── 工作台
│   ├── 工具列表
│   ├── 工具详情
│   └── 对话 / 会话
├── 档案
│   ├── 档案列表
│   ├── 新建 / 编辑档案
│   └── 档案详情与绑定工具
├── 快照与操作记录
├── 用量
└── 设置
    ├── 外观偏好
    ├── 本地数据与隐私说明
    └── 桌面与快捷入口（能力可用时）
```

导航说明：

- **工作台**是默认入口。左侧提供工具与会话上下文，主区域显示当前选择的工具或会话。
- **工具列表**始终保留未配置或异常工具，避免用户误以为扫描遗漏。
- **档案**与工具分开管理，避免把供应商资料误认为工具本身。
- **快照与操作记录**集中呈现可恢复状态和已经发生的写入。
- **用量**、桌面入口等按能力逐步开放；暂不可用时不显示空壳入口。

## 4. 页面职责

### 4.1 工作台 / 工具列表

**回答的问题：**「我有哪些工具？现在谁需要我处理？」

- 展示名称、安装/配置状态、当前供应商与模型摘要。
- 支持选择一个工具查看详情；工具身份与状态在列表中始终可见。
- 有多个工具时突出异常或待配置项，但不隐藏正常项。
- 空列表时解释如何安装/发现工具，并说明扫描不修改配置。

### 4.2 工具详情

**回答的问题：**「这个工具当前如何配置？我能做什么？」

按信息优先级组织：

1. 工具身份与状态、当前档案。
2. 供应商、接口地址、模型和密钥脱敏预览。
3. 配置路径、最后修改时间、诊断 warnings。
4. 可用动作：检查连通性、选择档案、预览并应用、查看快照、打开相关会话。

未配置和解析异常要给出原因及安全的下一步；只读状态不能伪装成可编辑状态。

### 4.3 对话与会话

**回答的问题：**「我在哪个项目下，正在和哪个工具工作？」

- 对话区域始终标明当前工具、项目目录和所用模型。
- 会话列表按项目与最近活动组织；历史记录可只读查看。
- 新建会话前明确项目目录；发送、停止、重试等状态与消息本身区分。
- 工具不支持应用内对话时，提供已支持的替代入口，而不是展示不可用输入框。

### 4.4 档案

**回答的问题：**「有哪些可用配置？它们正被哪些工具使用？」

- 档案列表显示名称、协议、供应商和绑定工具数。
- 编辑档案与应用档案到工具是两个不同动作。
- 删除前列出占用该档案的工具并阻止误删。
- 凭证只展示脱敏状态；不提供重新显示完整密钥的入口。

### 4.5 变更预览与快照

**回答的问题：**「应用后会改什么？如果不符合预期如何撤销？」

- 预览页展示目标工具、逐字段 before/after、潜在重启要求。
- 用户必须显式确认才能写入；取消后返回原页面且不产生变更。
- 完成页说明结果并链接到本次快照、操作记录和回滚动作。
- 外部文件变化导致应用被拒绝时，解释冲突并保留取消/重新检查路径。

### 4.6 设置

设置只放全局偏好与应用级能力：外观偏好、隐私与本地数据说明、快捷入口等。工具级配置仍留在工具详情或档案中，不重复提供第二个编辑入口。

## 5. 关键用户流程

### 流程 A：首次查看本机工具

```text
打开工作台
→ 查看扫描中的状态
→ 工具列表展示正常 / 未配置 / 异常条目
→ 选择一项查看详情
→ 根据状态查看配置摘要或可读原因
```

没有发现工具时展示空状态；单个工具读取失败不阻塞其他工具。

### 流程 B：将档案应用到工具

```text
工具详情选择「切换档案」
→ 选择已有档案
→ 查看逐字段变更预览
→ 确认应用 或 取消
→ 查看写入结果与快照入口
→ 必要时回滚
```

任何确认之前都不写入；档案编辑不自动同步到工具。

### 流程 C：开始一次项目会话

```text
工作台选择工具
→ 选择或添加项目目录
→ 确认工具与当前模型
→ 新建会话
→ 查看消息、执行中状态与结果
→ 从会话列表恢复或只读回放
```

### 流程 D：诊断工具异常

```text
工具列表发现异常徽标
→ 打开工具详情查看具体 warning
→ 在支持时主动运行健康检查
→ 根据结果调整档案或维持现状
→ 若应用配置，先预览并保留快照
```

健康检查是诊断动作，不隐式修改配置。

## 6. 状态与反馈约定

| 状态 | 信息架构要求 |
|---|---|
| 加载 / 扫描中 | 告知正在检查；避免先显示「正常」再跳变 |
| 空列表 | 说明尚未发现工具，并提供下一步提示 |
| 未配置 | 保留工具条目，说明缺少托管配置 |
| 异常 / 部分失败 | 指出受影响工具和原因，其他有效结果仍可访问 |
| 无权限 / 不支持 | 解释能力边界，不显示会失败的操作入口 |
| 写入中 | 锁定重复提交，明确操作正在进行 |
| 写入失败 | 明确失败与是否已回滚，不出现成功态 |
| 无数据 | 说明如何产生数据，区分「还没有」与「加载失败」 |

所有破坏性或写入动作都要在确认前说明目标与影响；危险操作不依赖颜色单独传达。

## 7. 当前范围与后续能力

当前回退后的前端仍保留首页、健康状态和工具发现/详情页面；本文件定义后续整体产品的信息架构，不代表档案、快照、聊天等页面已经实现或接入。

后续页面按后端能力逐步接入：档案与切换、快照/审计、健康检查、会话与聊天、用量、外观、引导和桌面能力。入口只有在具备可验证的功能与空/错误状态后才开放。

## 8. 本文不决定的事

- 色彩、字体、图标、圆角、动效、背景、气泡和布局尺寸。
- 具体组件库、页面视觉稿与响应式断点。
- 未在现有需求或决策中明确的功能取舍。

这些内容留给后续视觉设计与用户评审；本文件只作为页面结构和任务流的起点。
