# 01 — 信息架构

> 状态：示例基线，可按实际用户测试继续调整。
> 目标：先说明「用户要做什么、信息放在哪里、页面之间如何衔接」，不限定视觉风格。

## 1. 设计目标

CC-Roster 是本机 AI 编程工具的统一控制台。用户打开后应能快速回答：

1. 本机发现了哪些 AI 工具，各自配置是否正常？
2. 当前工具使用哪个供应商和模型？
3. 如何在确认影响后切换配置，并在出错时恢复？

信息架构优先服务于「查看工具 → 理解状态 → 决定下一步」；聊天是围绕工具与项目展开的工作区，不取代配置管理主线。

## 2. 核心对象与关系

| 对象 | 用户理解 | 关系 |
|---|---|---|
| 工具 | 已安装或被发现的 AI 编程工具，例如 Claude Code、Codex CLI | 一个工具对应一个稳定的列表条目 |
| 供应商 | 一组模型访问配置：模型列表、密钥引用、请求地址等 | 一个工具可绑定多个供应商，任一时刻只有一个是生效的 |
| 项目 | 用户选择的本地工作目录 | 会话归属于项目，并关联使用的工具 |
| 会话 | 与某个工具进行的一段对话或历史记录 | 属于项目；可继续、查看或只读回放 |
| 操作记录 | 用户可读的配置变更审计信息 | 记录操作时间、目标工具、字段变更和结果 |

产品规则：工具是主导航中的稳定对象；供应商是工具可使用的配置资源；项目用于组织工作上下文。切换供应商不改变工具的身份。

## 3. 全局导航

```text
应用
├── 工作台
│   ├── 工具列表
│       └── 对话 / 会话
|           ├── 新建会话
|           ├── 历史对话
|           └── 使用模型，模型思考强度
├── 供应商
│   ├── 工具列表
│       └── 供应商列表
|           └──模型列表，请求地址等
├── 操作记录
├── 用量
└── 设置
    ├── 外观偏好
    ├── 本地数据与隐私说明
    └── 桌面与快捷入口（能力可用时）
```

导航说明：

- **工作台**是默认入口。左侧提供工具与会话上下文，主区域显示当前选择的工具或会话。
- **工具列表**始终保留未配置或异常工具，避免用户误以为扫描遗漏。
- **供应商**与工具分开管理，避免把供应商资料误认为工具本身。
- **操作记录**集中呈现已经发生的写入，删除，切换供应商操作。
- **用量**、桌面入口等按能力逐步开放；暂不可用时不显示空壳入口。

## 4. 页面职责

### 4.1 工作台 / 工具列表

**回答的问题：**「我有哪些工具？现在谁需要我处理？」

- 展示名称、安装/配置状态、当前供应商与模型摘要。
- 有多个工具时突出异常或待配置项，但不隐藏正常项。
- 空列表时解释如何安装/发现工具，并说明扫描不修改配置。


### 4.2 对话与会话

**回答的问题：**「我在哪个项目下，正在和哪个工具工作？」

- 对话区域始终标明当前工具、项目目录和所用模型，思考强度。
- 会话列表按项目与最近活动组织；历史记录可只读查看。
- 新建会话前明确项目目录；发送、停止、重试等状态与消息本身区分。
- 工具不支持应用内对话时，提供已支持的替代入口，而不是展示不可用输入框。

### 4.3 供应商

**回答的问题：**「有哪些可用配置？它们正被哪些工具使用？」

- 按工具分组展示可绑定的供应商，并标出当前生效项。
- 工具列表显示已有的供应商，以及工具正在使用的供应商。
- 编辑供应商与应用供应商到工具是两个不同动作。
- 删除供应商前列出仍绑定它的工具并阻止误删。
- 可从本地导入模型供应商

### 4.4 设置

设置只放全局偏好与应用级能力：外观偏好、隐私与本地数据说明、快捷入口等。工具级配置仍留在工具详情或供应商页中，不重复提供第二个编辑入口。

## 5. 关键用户流程

### 流程 A：首次查看本机工具

```text
打开工作台
→ 查看扫描中的状态
→ 工具列表展示正常 / 未配置 / 异常条目
→ 选择一项进行对话
```

没有发现工具时展示空状态；单个工具读取失败不阻塞其他工具。

### 流程 B：将供应商应用到工具

```text
工具详情选择「切换供应商」
→ 选择已有供应商
→ 确认应用 或 取消
```

任何确认之前都不写入；供应商编辑不自动同步到工具。

### 流程 C：开始一次项目会话

```text
工作台选择工具
→ 选择或添加项目目录
→ 确认工具与当前模型，思考强度。
→ 新建会话
→ 查看消息、执行中状态与结果
→ 从会话列表恢复或只读回放
```

### 流程 D：诊断工具异常

```text
工具列表发现异常徽标
→ 打开工具详情查看具体 warning
→ 在支持时主动运行健康检查
→ 根据结果调整供应商或维持现状
→ 若应用配置，先预览并保留快照
```

### 流程 E：添加供应商

```text
对工具供应商的操作
→ 进入供应商页，按工具分组选择目标
→ 选择对供应商的删除，添加，修改，本地导入操作
→ 根据结果调整供应商或维持现状
→ 一键切换供应商
```

健康检查是诊断动作，不隐式修改配置。

## 6. 状态与反馈约定

| 状态 | 信息架构要求 |
|---|---|
| 加载 / 扫描中 | 告知正在检查；避免先显示「正常」再跳变 |
| 空列表 | 说明尚未发现工具，并提供下一步提示 |
| 未配置 | 保留工具条目，说明缺少托管配置 |
| 异常 / 部分失败 | 指出受影响工具和原因，其他有效结果仍可访问 |
| 无权限 / 不支持 | 解释能力边界，不显示会失败的操作入口 |
| 写入中 | 锁定重复提交，明确操作正在进行 |
| 写入失败 | 明确失败与是否已回滚，不出现成功态 |
| 无数据 | 说明如何产生数据，区分「还没有」与「加载失败」 |

所有破坏性或写入动作都要在确认前说明目标与影响；危险操作不依赖颜色单独传达。

## 7. 当前范围与后续能力

当前回退后的前端仍保留首页、健康状态和工具发现/详情页面；本文件定义后续整体产品的信息架构，不代表供应商、快照、聊天等页面已经实现或接入。

后续页面按后端能力逐步接入：供应商与切换、本地导入供应商，添加供应商、健康检查、会话与聊天、用量、外观、引导和桌面能力。入口只有在具备可验证的功能与空/错误状态后才开放。

## 8. 本文不决定的事

- 色彩、字体、图标、圆角、动效、背景、气泡和布局尺寸。
- 具体组件库、页面视觉稿与响应式断点。
- 未在现有需求或决策中明确的功能取舍。

这些内容留给后续视觉设计与用户评审；本文件只作为页面结构和任务流的起点。
