## ADR-001 项目名与应用标识

**状态**：已接受（2026-11-08）

**背景**：需求 §9 第 1 条；项目名会影响包名、窗口标题、数据目录、安装包 ID 与仓库地址。

**决策**：

- 数据目录名：Windows / macOS 用 `CC-Roster`，Linux 用 `cc-roster`（遵循 XDG 小写惯例）。
- 本文确认后不再改名；若必须改名，另开迁移卡，处理数据目录迁移与旧目录提示。

## ADR-002 「好友」的粒度

**状态**：已接受（2026-11-08）

**背景**：需求 §9 第 2 条；直接影响 F-06 列表信息密度、F-08 会话归属、F-09 视觉身份。

**决策**：

- **一个已安装或被配置的工具 = 一个好友**。好友 ID 使用工具 ID（如 `claude-code`、`codex-cli`）。
- 好友不是持久化实体，而是由「工具 + 当前生效档案 + 状态 + 外观」派生出的视图。
- 当前使用的供应商档案是好友的**属性**，不是新的好友。同一工具在多份档案间切换时，好友条目不变。
- 会话归好友下的**项目目录**分组；同一好友在不同目录的会话不混在一起。
- 已安装但未配置的工具同样出现在列表，状态为「未配置」。
- 默认外观的主色按**工具身份**推导，保证切换档案时颜色不跳变；供应商 / 模型家族只影响次级强调色。
  用户手动覆盖外观时，覆盖优先。

**理由**：

- 列表稳定，符合 F-01「已安装但未配置也要列出」与 F-06「一眼看出谁在这里」。
- F-09 的视觉识别不会因换 key / 换中转而失效。
- F-13 群聊的对比对象仍是不同的 AI，而不是同一 AI 的多份档案。

**已考虑但未采用**：

- 「工具 × 档案 = 一个好友」：会把同一工具拆成多条，列表随档案数量膨胀，且 F-01 的
  「未配置也要列出」会变得含糊。
- 「工具 × 项目 = 一个好友」：项目目录是会话上下文，不应提升为好友身份。

**边界**：

- 同一工具同时只有一个生效档案；切换后旧档案仍保留在档案库中。
- 若工具未安装，不产生好友；只在发现结果的 warnings 中体现。

## ADR-003 档案与工具配置的关系

**状态**：已接受（2026-11-08）

**背景**：需求 F-03、F-04；N-1、N-2、N-4。

**决策**：

- 供应商档案常驻应用侧，可新增、编辑、复制、删除、复用。
- 每个工具在任一时刻只有**一个生效档案**；工具配置文件里只保留当前生效值。
- 把档案应用到工具是一次显式操作：预览 → 确认 → 快照 → 写入 → 回读校验。
- **不做后台自动同步**；外部工具改了配置，本应用不自动覆盖。
- 写入完成后，工具配置文件是运行时的唯一真相源；应用侧档案只是「可复用的配置模板」。
- 检测到目标文件在上次读取后被外部改动，拒绝覆盖，返回冲突详情，由用户选择保留哪一边
  （本应用不自动合并）。
- 删除档案前必须检查占用；有工具绑定时列出占用方，未确认不得删除。

**后果**：

- 006 实现档案库与绑定关系；008 实现预览 / 切换。
- 应用数据被删除时，已应用到工具文件里的配置仍然存在；档案库丢失需要用户重新建立。

## ADR-004 全局只读模式

**状态**：已接受（2026-11-08）

**背景**：需求 §9 第 5 条；N-2 的强化项。

**决策**：

- 做全局只读模式，放在 016 实现，不阻塞 P0 闭环。
- 开启后，所有可能写文件的端点统一拒绝（切换、回滚、快照清理、档案导入等），返回可读的
  `READ_ONLY_MODE` 错误；读取、预览、健康检测、会话回放仍可用。
- 关闭必须由用户在界面上显式操作，不允许隐式关闭。
- 该设置存 `settings.json`，不随索引 / 缓存删除而重置。

**后果**：

- 016 增加统一的写端点拦截层；008 的 apply 必须经过该层。
- 界面常驻显示只读状态，避免用户误以为写入成功。

## ADR-005 应用形态与本地安全边界

**状态**：已接受（2026-11-08）

**背景**：需求 N-6、N-7；F-11、F-17；README 目标架构中的 Web / Tauri。

**决策**：

- P0 / P1 核心功能先做**本地 Web**：
  - 后端 FastAPI 仅监听 `127.0.0.1`。
  - 开发态：Vite dev server + `/api` 代理。
  - 交付态：前端构建产物由 FastAPI 静态托管，用户打开本机地址。
- P1 由 015 加 **Tauri 薄壳**，只负责窗口、托盘、快捷键、自启与后端进程生命周期；
  业务逻辑仍然在后端，不在壳里复制。
- 本地安全边界：
  - 禁止监听 `0.0.0.0`，不提供局域网 / 远程访问。
  - CORS 只允许本地前端来源。
  - Tauri 模式使用随机端口 + 启动令牌（或严格 Origin 校验），防止本机其他网页调用写接口。
  - 请求体大小设上限，避免本地接口被滥用。
- 若 015 被取消，F-17（托盘 / 全局快捷键 / 开机自启）明确移出范围，并在 `PROGRESS.md` 记录。
- 外部请求只允许两类：用户主动发起的模型调用、用户主动触发的健康检测；无遥测、无云端账号。

**后果**：

- 003 落实监听地址、CORS、请求体限制。
- 015 只做壳与生命周期，不重写前端业务。
- 017 的三平台发布验证覆盖 Web 与桌面壳两种形态。

## ADR-006 密钥存储与脱敏

**状态**：已接受（2026-11-08）

**背景**：需求 F-03「档案是配置，密钥是凭证」；N-5；D-6。

**决策**：

- 档案只存 `SecretRef`，**绝不存明文密钥**。
- `SecretStore` 抽象：
  - 首选 OS keyring：Windows Credential Manager / macOS Keychain / Linux Secret Service。
  - 不可用时回退到 `<data>/secrets.json`，Unix 权限 `0600`；Windows 依赖用户目录 ACL。
  - 回退状态必须在界面明确告知，不能静默降级。
- keyring 依赖在 006 引入时写明理由并更新 `uv.lock`；P0 早期可在 003 先定义接口，
  用内存假实现跑测试，006 再落地真实后端。
- 密钥命名：service `cc-roster`，username 使用 `profile_id`；删除档案时同步清理密钥。
- 脱敏规则（统一函数，前后端共用同一套文案规则）：
  - 长度 ≤ 8：全部替换为 `****`。
  - 长度 9～16：保留前 2 + `****` + 后 2。
  - 长度 > 16：保留前 4 + `****` + 后 4。
  - 不提供「完整显示密钥」的 API 或界面入口。
- 前端只收到 `has_secret: bool` 与脱敏值；编辑档案时留空表示保持原密钥。
- 日志、错误响应、审计记录、快照 diff、健康检测结果全部经过统一脱敏；测试用假 key 做全链路断言。
- 回退文件**不加密**；威胁模型仅覆盖「同机其他普通用户 / 误上传」，不承诺抵抗同用户恶意进程或管理员。

**后果**：

- 004 的读取展示、006 的档案编辑、009 的体检错误、016 的泄露扫描都必须调用同一脱敏函数。
- 003 的日志过滤器与 016 的扫描测试是本决策的机器化验收。

## ADR-007 数据目录与可删除语义

**状态**：已接受（2026-11-08）

**背景**：需求 N-1；D-7；F-05 快照。

**决策**：

数据根目录：

| 平台 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\CC-Roster` |
| macOS | `~/Library/Application Support/CC-Roster` |
| Linux | `${XDG_DATA_HOME:-$HOME/.local/share}/cc-roster` |

目录与文件：

| 路径 | 内容 | 可删除重建 | 删除后的影响 |
|---|---|---|---|
| `db/app.sqlite3` | 索引、缓存、审计、外观、健康检测缓存 | 是（审计 / 外观 / 体检历史会丢） | 工具配置、会话历史、档案不受影响；应用可重建索引 |
| `cache/` | 扫描 / 解析缓存 | 是 | 无影响 |
| `logs/` | 应用日志（已脱敏） | 是 | 无影响 |
| `snapshots/` | 快照内容 + 元数据 | 否（历史） | 回滚历史丢失；当前配置不受影响 |
| `profiles.json` | 档案 + 工具绑定 | 否（用户数据） | 应用侧档案丢失；已应用到工具文件的配置仍在 |
| `settings.json` | 全局设置（只读模式、体检频率、自启、快捷键等） | 否 | 恢复默认值 |
| `secrets.json` | keyring 不可用时的密钥回退 | 否 | 回退密钥丢失；keyring 中的密钥不受影响 |

实现约定：

- SQLite 使用 `PRAGMA user_version` + 幂等迁移，不引入 Alembic。
- 开启 WAL、设置 busy timeout；单进程优先，文件锁保护 `profiles.json` / `secrets.json`。
- JSON 写入使用「临时文件 + `os.replace`」原子替换。
- `profiles.json` 是可读 JSON，允许用户手工备份；不做自动云同步。
- 删除 `db/app.sqlite3`、`cache/`、`logs/` 后重启，应用必须能重建索引，且工具配置与会话历史不受影响。
  该场景在 017 做演练验收。

**后果**：

- 003 实现路径解析、SQLite bootstrap、原子写与文件锁。
- 006 的档案与 007 的快照按本表落盘。
- 017 的 N-1 验收只删除「可删除」列，不碰用户数据。

## ADR-008 新手引导的合规边界

**状态**：已接受（2026-11-08）

**背景**：需求 F-16；§9 第 4 条；明确不做第 2、7、8 条。

**决策**：

- 引导流程只做：环境检测 → 获取密钥指引 → 填入凭证 → 首条消息。
- **不代用户注册账号、不代用户购买、不提供共享账号或账号池**。
- 优先推荐官方供应商与官方文档；推荐第三方中转时必须显示免责声明，不接联盟返利。
- 不自动安装工具；如需给出安装命令，必须展示命令并由用户确认后执行。
- 不接管登录态；OAuth 凭据只做备份 / 还原，不解析、不迁移、不共享。
- 引导进度可中断续做；每一步显示当前进度、失败原因与下一步。

**后果**：

- 021 的文案与流程必须通过本 ADR 检查；涉及第三方推荐的部分在 UI 上可关闭。
- F-16 不改变 P0/P1 的核心闭环，仍为 P2。

## 附录 A 工具适配器契约

后续适配器（Claude Code、Codex CLI、Gemini CLI、OpenCode 等）统一实现以下契约。
契约是 004、020 的验收基线；新增适配器不得修改已有适配器的行为。

### A.1 元数据与能力

| 字段 | 含义 |
|---|---|
| `id` | 稳定标识，如 `claude-code`、`codex-cli` |
| `display_name` | 界面显示名 |
| `capabilities.read` | 必须为真；能发现并解析配置 |
| `capabilities.write` | 能否生成 / 应用配置计划 |
| `capabilities.sessions` | 能否列出 / 读取会话记录 |
| `capabilities.launch` | 能否生成启动终端的计划 |
| `write_mode` | `none` / `managed_fields`；`managed_fields` 表示只改管辖字段 |

### A.2 方法

| 方法 | 职责 | 是否允许写盘 |
|---|---|---|
| `detect()` | 返回是否安装、是否配置、版本、配置文件、最后修改时间、warnings | 否 |
| `managed_paths()` | 返回本适配器管辖的配置文件路径 | 否 |
| `read()` | 解析当前配置，返回托管字段、原始 hash、解析 warnings | 否 |
| `plan(profile, current)` | 生成逐字段 before / after、目标文件、重启要求、blockers | 否 |
| `render(plan, original_text)` | 返回写入后的文本；必须保留注释 / 键序 / 未知字段 | 否（纯函数） |
| `verify(plan, actual_text)` | 回读校验：托管字段符合预期，且未知内容未被破坏 | 否 |
| `list_sessions()` | 列出会话引用（工具、项目目录、时间、源文件） | 否 |
| `read_session(ref)` | 读取并归一化一条会话 | 否 |
| `launch_spec(profile, project_dir)` | 返回命令、环境变量、临时配置覆盖方案 | 否 |

### A.3 错误分类

| 错误 | 触发条件 | 应用行为 |
|---|---|---|
| `NotInstalled` | 找不到工具 | 不出现在好友列表 |
| `NotConfigured` | 已安装但无配置 | 好友状态「未配置」 |
| `ParseError` | 配置损坏 / 缺字段 | 好友状态「异常」+ 具体原因 |
| `PermissionDenied` | 目录 / 文件无权限 | 降级只读并告知 |
| `UnsupportedVersion` | 版本超出已知范围 | 降级只读，不猜测字段 |
| `UnsupportedCapability` | 适配器不支持某能力 | 对应入口隐藏或禁用并说明 |
| `UnsafeWrite` | 无法保证保留未知内容 | 拒绝写入，建议手工处理 |
| `Conflict` | 文件被外部改动 | 拒绝覆盖，返回冲突详情 |

### A.4 契约规则

1. `detect` / `read` / `plan` / `render` / `verify` 一律不得写盘；写盘只由 007 的写引擎执行。
2. `render` 是纯函数；同样的输入必须得到同样的输出。
3. 无法保证保留注释、键序、未知字段时，返回 `UnsafeWrite`，不得「先写了再说」。
4. `verify` 同时校验托管字段与未知内容 hash；任一不符即判定失败并触发还原。
5. 适配器不做网络请求；健康检测属于 009 的独立服务。
6. 适配器注册使用显式清单，v1 不做从任意路径动态加载插件。
7. 新增适配器必须通过共享 contract test；已有适配器的测试不得因新增而修改断言。

## 附录 B 领域模型

| 实体 | 关键字段 | 持久化 | 说明 |
|---|---|---|---|
| `Tool` | `id`、名称、安装 / 配置状态、版本、配置路径、最后修改时间、warnings | 扫描派生（可缓存） | 一个工具最多一个好友 |
| `Profile` | `id`、名称、协议类型、base_url、`secret_ref`、模型清单、时间戳 | `profiles.json` | 档案是配置模板 |
| `SecretRef` | `id`、`backend`（keyring / file）、`locator` | `profiles.json`（仅引用） | 不含明文 |
| `ToolBinding` | `tool_id`、`profile_id`、是否生效、应用时间、快照 ID | `profiles.json` | 每个工具至多一个生效绑定 |
| `Snapshot` | `id`、`tool_id`、时间、文件列表、hash、diff 摘要、是否 pin、原因 | `snapshots/` + 元数据 | 回滚依据 |
| `Session` | `id`、`tool_id`、项目目录、源文件、开始 / 更新时间、消息数 | 从工具记录读取，SQLite 缓存 | 只读 |
| `Message` | `id`、`session_id`、角色、内容、时间、工具名、原始引用 | 派生 | 角色：user / assistant / tool_call / tool_result |
| `HealthCheck` | `id`、`profile_id`、状态、耗时、错误码、人话原因、时间 | SQLite 缓存 | 失败不修改配置 |
| `AuditEntry` | `id`、时间、动作、工具、档案、文件、字段、快照 ID、结果 | SQLite | 可读操作记录 |
| `Appearance` | 好友 ID、主题色、背景、气泡样式、来源（默认 / 手动） | SQLite | 可删除重建；手动覆盖丢失后回落默认 |
| `Settings` | 只读模式、后台体检频率、自启、快捷键等 | `settings.json` | 不随索引删除 |
| `Friend` | 工具 ID、显示名、状态、当前档案、外观、最近使用时间 | **派生，不持久化** | 好友是视图 |

关系：

- `Tool 1—N ToolBinding`，且同一时刻至多一个 `active`。
- `Profile 1—N ToolBinding`。
- `Tool 1—N Snapshot`、`Tool 1—N Session`；`Session 1—N Message`。
- `Profile 1—N HealthCheck`。
- `Friend = Tool + active Profile + 状态 + Appearance`。

标识与格式：

- ID 使用 UUID4 字符串；时间使用带时区的 ISO 8601（UTC）。
- 金额 / 花费使用 `Decimal`，序列化为字符串。
- 枚举值在 JSON / SQLite 中存字符串，读取时校验，未知值按错误处理而不是猜测。

好友状态：

| 状态 | 含义 |
|---|---|
| `ok` | 已配置、可解析，且最近一次已知体检未失败 |
| `unconfigured` | 已安装但未配置 |
| `error` | 配置解析失败、无权限，或最近一次体检失败 |
| `checking` | 正在检测 / 扫描 |
