# 产品需求文档（Requirements）

> 状态：草案 v0.1
> 范围：**只写"要什么、为什么、做到什么程度算达成"，不写怎么实现，也不写排期与步骤。**
> 实现的任务划分与验收流程见 `specs/` 下的任务卡。

---

## 1. 一句话定位

一个只在本机运行的**统一控制台**：把电脑上各个 AI 编程工具（Claude Code、Codex CLI 等）的模型与供应商配置集中管起来，并用**类似微信聊天界面**的方式，把每个 AI 呈现为一个"好友"。

它管的是**配置**，不是模型本身；它不产生新的 AI 能力，只让已有的 AI 工具**可被看见、可被切换、可被撤销、可被读懂**。

---

## 2. 为什么做（问题陈述）

当前（2026）主流 AI 编程工具的现状，构成了下面这些具体痛点：

| # | 痛点 | 具体表现 |
|---|---|---|
| P-1 | 配置分散、格式各异 | 每个工具在自己的用户目录里放自己的配置文件，格式不同、字段不同，想改一次要翻几份文档 |
| P-2 | 手改易错 | 换 key、换中转地址、换模型都要手改配置文本；改错一个引号，工具直接起不来，且报错不指向那行 |
| P-3 | 没有后悔药 | 改坏了只能凭记忆手改回去；登录态、历史记录可能一起丢 |
| P-4 | 不知道"还能不能用" | 配置写着不等于能通。key 过期、中转挂了、模型下架，都只有等你真的用的时候才发现 |
| P-5 | 会话记录埋在文件里 | 历史对话存在各自的日志文件里，只能靠命令行翻，没有可读的视图 |
| P-6 | 多个 AI 之间没有统一视图 | 用户记不住"我现在这个终端里跑的是哪家的哪个模型"，也记不住"上次那个好用的配置叫什么" |
| P-7 | 新手门槛高 | 对没接触过 AI 的人，装工具、找 key、填配置是三道墙，且没有任何界面告诉他"你现在缺哪一步" |

**核心判断**：P-1～P-4 是工程痛点，P-5～P-7 是体验痛点。前者决定这个工具**有没有用**，后者决定它**愿不愿意被打开**。

---

## 3. 目标用户

| 优先级 | 用户 | 特征 | 他要什么 |
|---|---|---|---|
| 主要 | 个人开发者 / 技术学生（含作者本人） | 本机已装 ≥1 个 AI 编程工具，可能同时用官方、中转、本地模型 | 少花时间在配置上，配置出错能立刻知道、能一键还原 |
| 次要 | 已装工具但不太会配的同学 | 工具装了，key 填了，但不知道对不对，也不敢改 | 一个能告诉他"哪里不对"的面板 |
| 远期 | 几乎没接触过 AI 的普通人 | 没有工具、没有 key，不知道 base_url 是什么 | 一个**向导**，而不是一个**面板** |

> 边界提醒：第三类用户**用不了配置面板**——他没有配置可管。对他而言需要的是"安装 + 填 key + 跑通第一条消息"的引导流程，这是独立功能（见 F-16），不能和主功能混为一谈。

---

## 4. 功能需求

优先级含义：**P0 = 第一个可用版本必须全部具备**，缺任何一条都不构成"能给别人看"的版本；**P1 = 体验成型**；**P2 = 有余力再做**。

### 4.1 P0 — 核心闭环

#### F-01 环境发现
- 自动识别本机**已安装或已配置**的 AI 编程工具，无需用户手动指定路径。
- 对每个工具至少给出：名称、是否已配置、配置的最后修改时间。
- 已安装但未配置的工具也**必须列出**，状态标为"未配置"，而不是从列表里消失。
- 不认识的工具/目录结构不得导致整体失败：忽略并继续，且整体结果里能看出"有东西没被识别"。

**验收要点**：在一台装着 Claude Code 但从未配置过 Codex 的机器上打开，界面能同时出现这两个条目，且状态不同。

#### F-02 配置读取与展示（只读）
- 解析各工具的生效配置，展示：当前使用的供应商、接口地址、模型名、是否为第三方中转。
- **密钥一律脱敏展示**（只露前若干位与后若干位），界面上不存在"完整显示密钥"的入口。
- 配置损坏、缺字段、格式不认识时，展示为"解析失败 + 原因"，而不是空白或整体报错。
- 本功能**不修改任何文件**，只读。

**验收要点**：手工把某份配置改坏一个字符，界面显示具体的坏在哪，且其余工具仍正常展示。

#### F-03 供应商档案与模型清单
- 用户可以建立一组**与工具解耦的供应商档案**：名称、协议类型、接口地址、密钥、该供应商下可用的模型清单。
- 同一份档案可被多个工具复用；同一个工具也可在多份档案之间切换。
- 档案可新增、编辑、复制、删除；删除前须提示有哪些工具正在使用它。
- 密钥与档案分开存放的概念上要成立：用户应能理解"档案是配置，密钥是凭证"。

**验收要点**：新建一份档案并复用到两个工具上；删除该档案时被明确拦下并列出占用方。

#### F-04 一键切换（含改动预览）
- 把某份供应商档案应用到某个工具，是**一次明确的操作**，不是后台自动同步。
- 执行前**必须**展示逐字段的前后对比（before / after），用户可以看清到底改了什么。
- 用户取消时，磁盘上不得有任何变化。
- 执行后，工具侧下次启动即使用新配置（**若某工具必须重启才生效，界面必须明说，不得给出误导性的成功提示**）。

**验收要点**：切换后打开配置文件，内容是预期的那几项；其余内容逐字符未变。

#### F-05 快照、校验与回滚
- 任何写入动作之前**自动生成快照**，快照可在界面上看到（时间 + 涉及文件 + 改了什么）。
- 写入后**回读校验**：实际落盘的内容与预期不一致时，判定为失败并自动还原。
- 若检测到目标文件在"上次被本应用读取之后"被外部改动过（用户手改、其他工具改），**拒绝覆盖**并提示，让用户选择保留哪一边。
- 提供"回滚到某个快照"，回滚结果须与快照时逐字节一致。
- 快照有保留策略（保留最近若干份 / 手动固定的不被清理），不会无限增长。

**验收要点**：切换 → 手改文件 → 再切换被拦下 → 回滚后文件与最初完全一致。

#### F-06 界面骨架（微信式）
- 主界面为左右结构：左侧是 AI 列表（"好友"），右侧是该 AI 的详情/会话区。
- 列表条目至少包含：头像位、名称、一行状态描述、状态徽章（正常 / 未配置 / 异常 / 检测中）。
- 列表支持按最近使用排序；空状态有明确引导（"还没有发现任何 AI 工具，点这里看怎么装"）。
- 整体气质**接近即时通讯软件**：低认知负担、一眼看出"谁在这里、谁有话说"，而不是仪表盘式的图表堆叠。

**验收要点**：给一个没用过的人看 3 秒，他能说出"这是几个 AI 的列表"。

### 4.2 P1 — 体验成型

#### F-07 健康体检
- 对每份供应商档案发起**真实的可用性检测**，输出：是否连通、响应耗时、失败原因（用人话描述，如"密钥无效""地址不对""模型不存在"）。
- 检测是用户主动触发的，或按可控频率在后台进行；**不得在用户不知情时频繁打外部接口**。
- 检测失败**不得**影响配置本身——检测是诊断，不是修改。

**验收要点**：分别填入一个正确地址、一个错地址、一个错 key、一个不存在的模型，四种情况给出四种不同的可读结论。

#### F-08 会话历史回放（只读）
- 读取各工具已经产生的会话记录，按时间线渲染成消息气泡（用户/助手/工具调用区分展示）。
- 只读：不修改、不删除、不"整理"原始记录。
- 会话数量多时不卡顿；打开即用，不需要用户先"导入"。

**验收要点**：打开后能翻到自己昨天的一段真实对话，顺序与内容与原始记录一致。

#### F-09 每个 AI 独立外观
- 每个"好友"拥有**自己的视觉身份**：主题色、聊天背景、气泡样式。
- 默认外观**自动生成**（按模型家族/供应商推导），开箱即好看，不需要用户配置。
- 允许用户手动覆盖，但不强求——**默认状态就是完成状态**。
- 视觉差异要能承担识别功能：扫一眼列表就能靠颜色分辨是谁，而不是纯装饰。

**验收要点**：同时存在 5 个以上 AI 时，不读名字也能靠视觉区分。

#### F-10 在应用内发起对话
- 在界面输入一句话，交给对应的 AI 执行，结果**流式**呈现为气泡。
- 每次对话归属于一个明确的上下文（至少要知道"在哪个项目目录下干活"）。
- 执行过程中的中间状态（思考中、调用工具、等待确认）要可见，不能只有一个转圈。
- 用户可中断正在进行的对话。
- 失败时给出可读原因，并保留这次输入以便重试。

**验收要点**：在界面里让 AI 改一个小文件，能看到过程、能看到结果、能中断。

#### F-11 启动器
- 从界面一键在**指定项目目录**、用**指定供应商配置**启动对应的 AI 工具（打开一个可交互的终端窗口）。
- 启动前能看清"将在哪个目录、用什么配置启动"。

**验收要点**：点击后终端在正确目录打开，且工具读到的正是界面上选的那份配置。

#### F-12 搜索与筛选
- 按名称、供应商、模型、状态筛选列表；搜索结果即时反馈。

### 4.3 P2 — 扩展

#### F-13 群聊对比
- 同一个问题同时发给多个 AI，并排展示各自回答，并附耗时/成败对比。
- 任一 AI 失败不影响其他 AI 的结果展示。

#### F-14 用量与花费
- 汇总各 AI 的调用次数、token 消耗与估算花费，按时间线呈现。
- 只做展示与提醒，不做自动充值/计费。

#### F-15 更多工具适配
- 在 Claude Code / Codex CLI 之外，支持更多同类工具（如 Gemini CLI、OpenCode、Qwen Code 及主流 IDE 插件）。
- 适配是**可增量添加**的：新增一个工具不要求改已有工具的行为。

#### F-16 新手引导（面向普通人）
- 面向"什么都没有"的用户，逐步引导完成：安装工具 → 获取/填入凭证 → 跑通第一条消息。
- 每一步都能看到当前进度与失败原因；可随时退出并从上次的位置继续。
- 明确不代用户购买、不代用户注册、不提供共享账号。

#### F-17 常驻与快捷入口
- 托盘常驻、全局快捷键唤起、开机自启（默认关闭，用户显式开启）。

## 5. 非功能需求

| # | 要求 | 说明 |
|---|---|---|
| N-1 | **配置文件是唯一真相源** | 应用自身的数据（索引、缓存、外观设置）可随时删除并重建；删除后用户已有配置与历史不受任何影响 |
| N-2 | **只读优先** | 用户没有明确点击"应用/切换"之前，任何文件都不得被写入 |
| N-3 | **可逆** | 任何一次写入都能在一步操作内恢复到写入前状态 |
| N-4 | **不破坏未知内容** | 只修改属于本应用管辖的字段；注释、键序、未知字段、其他工具写入的内容必须原样保留 |
| N-5 | **密钥不泄露** | 界面脱敏；日志不出现明文密钥；错误提示里也不带完整密钥 |
| N-6 | **完全本地** | 无云端账号、无遥测、不上传任何配置或会话内容；唯一的外部请求是用户主动发起的模型调用与健康检测 |
| N-7 | **跨平台一致** | Windows / macOS / Linux 上功能与文案一致；路径、权限差异不得表现为"某个平台少一个功能" |
| N-8 | **优雅降级** | 遇到不认识的配置格式、超出预期的版本、无权限的目录时，降级为只读并明确告知，绝不猜测、绝不静默失败 |
| N-9 | **性能** | 上百个会话、几十 MB 的配置文件下，主界面 1 秒内可用；扫描不得阻塞界面 |
| N-10 | **诚实反馈** | "需要重启才生效""只能读不能写""这个格式我不认识"这类事实必须直说，不出现假的成功状态 |
| N-11 | **可审计** | 用户能看到本应用**改过哪些文件的哪些字段**（一份可读的操作记录） |

## 6. 明确不做（边界）

以下事项即使技术上可行也**不做**，用于防止范围蔓延：

1. **不做云端同步与账号体系**。没有登录、没有多设备同步、没有服务端。
2. **不做 API 转售、账号池、共享密钥**。不代他人转发请求，不提供"别人的 key 拿来用"的能力。
3. **不自己实现 Agent 能力**。工具调用、权限确认、沙箱、MCP 等一律交给被管理的工具本身；本应用只负责配置与呈现。
4. **不修改被管理工具的安装目录或程序本体**，只动它们的用户级配置。
5. **不做移动端**。
6. **不做模型训练、微调、本地推理引擎**。
7. **不绕过任何官方计费、授权或地区限制**。
8. **不接管用户的登录态**（OAuth 凭据只做备份与还原，不做解析、迁移或共享）。

## 7. 成功标准

用可观察的现象判断这个需求是否成立，而不是用"代码写完"判断：

1. 打开应用 **30 秒内**能说清"我电脑上有几个 AI、各自配的是什么、哪个有问题"。
2. 换一次供应商 **≤ 3 次点击**；失败后 **1 次点击**回到原状。
3. 把仓库交给一个陌生人：他能看懂这是干什么的、能跑起来、能截一张图。
4. 一个不太懂 AI 的同学，在无人指导的情况下能发出第一条消息（F-16 达成时）。
5. 作者本人连续两周**每天真的打开它**，而不是做完就放着。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| **工具（框架）** | 被管理的 AI 编程工具本体，如 Claude Code、Codex CLI |
| **供应商** | 提供模型接口的一方：官方、第三方中转、本地服务等 |
| **档案（Profile）** | 一组"供应商 + 地址 + 凭证 + 模型清单"的可复用配置 |
| **切换** | 把某份档案应用到某个工具，是一次显式、可预览、可撤销的写操作 |
| **快照** | 写入前的文件状态备份，是回滚的依据 |
| **会话** | 一次连续的对话上下文，通常绑定一个工作目录 |
| **好友** | 界面上对"一个可对话的 AI 条目"的称呼（工具 / 档案 / 会话的组合视角） |

## 9. 未决问题

1. **项目名未定**（当前 `README.md` 中为占位符）。名字会影响界面文案、包名与仓库地址，应在第一个可用版本前确定。
2. **"好友"的粒度**：一个工具算一个好友，还是"工具 × 项目"算一个好友？直接影响 F-06 与 F-08 的信息密度。
3. **是否需要"多套配置并存"**：同一工具保留多份档案并快速来回切（工作/个人/客户三套 key），还是只保留"当前生效"一份。
4. **F-16 的合规边界**：新手引导是否可以代用户申请官方密钥、是否可以推荐第三方中转；推荐行为是否需要免责说明。
5. **是否需要只读模式**（全局开关，开了之后整个应用不可能写文件）——如果要做，应作为 N-2 的强化项写进 P0。
