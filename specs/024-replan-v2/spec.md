# 024 — V2 任务计划重排

## 背景与目标
- 新信息架构以 `docs/design/01-ia.md` 为基线；旧 `docs/task-plan.md` 仍按“好友 / 微信式骨架”的旧需求编写，且后端已实现其中大部分能力，继续按旧卡排期会重复劳动。
- 产出一份只覆盖剩余工作的 V2 计划：决策清单、任务卡、依赖、里程碑、旧卡映射与明确不做项。
- 本卡只写规划文档，不写业务代码。

## 验收标准（DoD）
- `uv run python scripts/check.py` 退出码 0。
- `docs/task-plan2.md` 存在，并包含：当前基线、待拍板决策、任务卡总览、依赖与里程碑、详细任务卡、旧卡映射、风险与开工顺序。
- 计划明确区分：已完成后端能力、前端重建、后端增量、待确认决策、明确延后/不做的旧功能。
- 计划不把未拍板的方案写成既定事实；受影响任务卡必须标注决策前提。
- 不修改后端、前端或现有任务卡的业务实现。

## 范围

```scope
docs/design/01-ia.md
docs/task-plan2.md
```

## 边界用例（实现时必须想到）
1. 「档案 / 供应商」语义尚未拍板时，计划必须同时保留 A/B 方案的差异，不能只按一种方案排死。
2. 已由后端实现的能力（档案 CRUD、切换、快照、会话回放、用量、审计、设置等）不得重新排成从零开发。
3. 新 IA 未出现的旧功能（群聊、新手引导、搜索筛选、启动器等）必须显式标记为延后或不纳入，不能默默消失。
4. 前端入口只有在对应页面具备可用状态（含空 / 错误态）后才开放，不能先摆空壳导航。

## 不做（明确划界）
- 不修改后端、前端、`rules/`、`scripts/` 或 `docs/decisions.md`。
- 不创建计划中列出的后续任务卡；本卡只产出计划。
- 不决定视觉细节；tokens / components / acceptance 的具体内容留给 100 号卡。
- 不把旧 `docs/task-plan.md` 删除或改写；它作为历史基线保留。
