# 029 — 前端供应商页：供应商列表与 CRUD

> 来源：`docs/task-plan2.md` §5 的 103 号规划卡；正式编号 029（沿用「目录用规划编号、标题用正式编号」的约定）。
> 依赖：100（V2 决策与设计基线）、101（工作台应用壳）T1–T7 已完成、028（多供应商绑定）已提交。
> 性质：前端实现卡。只动 `frontend/src/**`；不改后端接口、不写工具配置文件、不做切换 / 应用。

## 背景与目标

1. 028 已让同一工具保存多条供应商绑定，并提供 `GET /api/profiles?tool_id=`、绑定、精确解绑、复制、删除保护与健康检查接口；前端还没有供应商页面，用户无法按工具查看和管理这些配置。
2. 目标 1：新增「供应商」一级页面。左侧选择工具，右侧显示该工具已绑定的供应商，标出 active，空 / 加载 / 错误 / 权限不足 / 密钥缺失都有可读状态。
3. 目标 2：覆盖供应商新增、编辑、复制、从当前工具移除、删除（含占用确认）与健康检查；编辑与删除只作用于供应商数据，不写工具配置、不改变 active。
4. 目标 3：复用现有 `api/client.ts`、`stores/tools.ts` 与设计 tokens，不新增第二套请求层或组件库。

## 开卡决策

- 页面采用两栏：左栏工具列表，右栏当前工具的供应商列表；窄屏改为上下布局。工具列表保留未配置 / 异常工具，方便用户先补齐配置。
- 「新增供应商」= 创建 `Profile` 后立即绑定到当前工具；新绑定 `active=false`，不自动激活、不写工具配置。若绑定失败，前端删除刚创建的供应商作为补偿；补偿失败时明确提示「已创建但未绑定」，不报假成功。
- 「复制」= 复制 `Profile` 后绑定到当前工具，同样保持 `active=false`。
- 「从当前工具移除」只调用 102 的精确解绑接口，不删除供应商；「删除供应商」才调用删除接口，并按后端 409 `PROFILE_IN_USE` 弹出占用工具确认。
- 当前 active 只读展示；切换 / 应用 / 预览 / 回滚留给 104，本卡不提供「应用」按钮。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0。
- 路由与导航：`/providers` 打开供应商页；主导航出现「供应商」条目，当前路由 `aria-current="page"`，工作台入口保持可用；除供应商外不新增空壳入口。
- 布局与选择：页面先展示工具，再展示所选工具的供应商；工具条目显示名称、安装 / 配置状态、已绑定供应商数量与当前 active 供应商摘要；未配置 / 异常工具仍可选；未选择工具时右栏显示引导，不请求供应商列表。页面加载时读取全量供应商与绑定用于工具摘要，选中工具后按 `tool_id` 读取该工具的供应商列表；操作成功后同时刷新汇总与当前列表。全量摘要读取失败时工具条目显示「—」，不得伪装成 0。
- 供应商列表：每项显示名称、协议、接口地址、模型清单摘要、密钥脱敏状态（`has_secret` + `secret_preview`，不显示明文）、绑定时间、active 徽章；无 active 时显示「未启用」；列表按绑定顺序稳定展示。
- 新增：表单覆盖名称、协议、接口地址、模型清单、密钥；密钥输入留空表示不设置；提交成功后供应商出现在当前工具列表且 `active=false`；重复名称 / 非法地址等后端错误原样、可读地显示，不关闭表单、不丢用户输入。
- 编辑：可修改名称、协议、接口地址、模型清单与密钥；密钥留空表示保持原值，提供「清除密钥」显式动作；保存后列表与详情同步，不改变 active、不写工具配置。
- 复制：复制当前供应商并绑定到当前工具；名称留空时使用后端生成的「原名 (副本)」；副本 `active=false`，原供应商状态不变。
- 移除：可从当前工具移除一条绑定，只移除该绑定，不删除供应商；重复移除按 `removed=false` 处理为幂等成功；供应商仍绑定其他工具时不影响其他工具。
- 删除：点击删除先打开确认浮层并显示供应商名称；用户确认后调用未确认删除。若返回 409 `PROFILE_IN_USE`，浮层切换为占用工具列表（含 `installed=false`）并要求再次确认；再次确认后调用 `confirm=true`，只删除该供应商及其绑定。任何一步取消都不发确认删除；非 409 错误可读显示。
- 健康检查：按钮有 loading 且禁止重复触发；结果展示状态、消息、耗时、检测模型与时间；`CONNECTED` 与非 `CONNECTED` 文案区分；`MODEL_REQUIRED` / `SECRET_MISSING` / `SECRET_STORE_ERROR` 可读；检测不修改供应商或工具配置；切换供应商时清除上一家的检测结果。
- 状态：工具列表、供应商列表、表单提交、删除、健康检查分别覆盖 loading / 空 / 错误；后端不可达、权限不足、密钥缺失有可读文案，不显示「正常」假状态。
- 可访问性：导航、工具条目、供应商条目、按钮、表单控件可用 Tab 到达；`:focus-visible` 可见；状态不只靠颜色；表单控件有 label；确认浮层可用 Esc 关闭并把焦点还给触发按钮；不使用 `outline: none` 移除焦点。
- 只使用 `docs/design/04-tokens.md` 的 CSS 变量；新增样式不写裸十六进制色值；无新依赖。
- 组件测试覆盖上述行为；手动验收表填写完整并记录 `check.py` 完整输出。

## 边界用例（实现时必须想到）

1. 工具列表为空 / 全部异常 / 单个工具未配置：页面仍可用，供应商区给出对应空状态。
2. 未选择工具 / 快速切换工具 A→B：B 的供应商列表不得被 A 的迟到响应覆盖；同一工具重复点击不重复请求。
3. 供应商列表为空、只有一条未启用、只有一条 active、多条混合：active 标记与「未启用」文案正确。
4. 创建表单：空名称、空地址、非法协议、超长名称 / 地址、重复模型、空模型列表、密钥留空 / 空白 / 超长、后端 422；校验错误留在表单内。
5. 创建 / 复制后绑定失败、补偿删除失败：不显示成功；提示供应商是否已创建。
6. 删除：点击删除先出现确认浮层；无占用时一次确认后删除；409 占用（含已卸载工具）时浮层列出工具并再次确认；任一步取消都不删除；确认删除失败；重复删除。
7. 编辑：密钥留空保持原值、显式清除、保存失败不丢表单；编辑不改变 active。
8. 移除：active 绑定被移除后不自动提升其他绑定；当前工具进入无 active；供应商仍存在于其他工具。
9. 健康检查：无模型、无密钥、超时、401、429、404、网络失败、重复点击；切换供应商时旧结果不得串台。
10. 长名称、长地址、长模型列表、长占用工具列表：不撑破布局、不出现整页横向滚动；完整值可查看。
11. 权限不足 / 后端不可达：工具与供应商区域分别显示可读错误，不互相拖垮。
12. 路由：直接访问 `/providers`、刷新、从工作台切到供应商再返回；导航高亮正确。

## 不做（明确划界）

- 不做切换 / 应用 / 预览 / 回滚 / 快照入口（104）。
- 不写工具配置文件，不改变 active；本卡只维护 `profiles.json` 的绑定与供应商 CRUD。
- 不做本地导入、去重、版本化 JSON（105）。
- 不改后端 `Profile` / `ToolBinding` / API 契约；如发现后端缺口，先记入未决问题。
- 不做搜索、筛选、排序（ADR-014）。
- 不做暗色模式、主题切换、移动端断点；窄屏只保证桌面最小宽度可用。
- 不引入组件库、图标库或新依赖；图标用内联 SVG。
- 不做全局供应商管理视图 / 未绑定供应商列表；本卡按工具管理。
