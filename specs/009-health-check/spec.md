# 009 — 健康体检

> 输入：`docs/task-plan.md` 的 009 卡；`docs/requirements.md` F-07 / N-5 / N-6 / N-10；`docs/decisions.md` ADR-006 / ADR-007；006 档案与密钥边界。
> 依赖：006 已完成。008 当前已完成；体检入口放在 006 的 `/profiles` 页面，不依赖切换流程。
> 本卡只实现用户主动触发的一次性档案连通性检测；体检是诊断，不修改工具配置或档案。

## 开卡决策

1. **只由用户触发**：本卡不实现后台定时体检或自动重试，避免用户不知情的外部请求；不新增频率设置。
2. **一次最小真实请求**：按 `Profile.protocol` 和所选模型发出一次非流式探测，不发送用户对话内容；前端明确提示请求可能产生少量费用。设置有限超时，不跟随重定向，避免把密钥转发到其他地址。
3. **模型选择**：默认档案模型清单第一项；可选择清单内其他项。清单为空时不发网络请求并给出可读结论。模型在档案清单中但供应商不接受时，归类为「模型不存在」。
4. **结果不持久化**：只返回本次结果并在页面展示；不新增 SQLite 表、体检历史 API 或后台任务。本卡不改变工具发现状态。
5. **无新依赖**：复用项目已有运行时能力；若现有依赖无法满足协议请求，不得擅自新增依赖，先更新本卡并说明理由。

## 背景与目标

1. F-07 要求对供应商档案做真实可用性检测，给出连通性、耗时和可读失败原因。
2. 用户能从档案管理页主动检查地址、凭证和模型；失败只说明诊断结果，不改变档案、密钥或工具配置。
3. 将网络超时、认证失败、地址错误、模型不存在、限流与未知错误映射为稳定结果码；错误响应、日志和界面均不得泄露完整密钥或原始上游响应。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0，完整输出记录在本卡 `tasks.md`。
- `POST /api/profiles/{profile_id}/health-check` 接受 `{model?: string}`，返回显式类型 `HealthCheckResponse {profile_id, model, status, attempted, duration_ms, message, checked_at}`；未知档案返回统一 404。
- `status` 至少区分 `CONNECTED`、`INVALID_CREDENTIALS`、`INVALID_ADDRESS`、`MODEL_NOT_FOUND`、`TIMEOUT`、`RATE_LIMITED`、`SECRET_MISSING`、`SECRET_STORE_ERROR`、`MODEL_REQUIRED`、`UNKNOWN`；每种结果都有中文可读说明。`duration_ms` 为非负整数或 `null`；未发起网络请求时 `attempted=false`、耗时为 `null`。
- 按档案协议和所选模型向档案 `base_url` 发起一次真实、最小化的非流式探测；超时有上限、不自动重试、不跟随重定向、不发送用户内容。无模型时不发网络请求。
- 体检前后档案、密钥存储、工具配置文件、快照和审计数据均不变；不会自动或周期性产生外部请求。
- 密钥只用于本次请求；响应、日志、异常、界面和测试捕获的诊断文本均不含完整密钥，也不回显未经处理的上游响应正文。
- `/profiles` 每份档案都能由用户主动发起体检：模型选择可用、加载态明确、重复点击受控；显示耗时与可读结果，失败可重试，不出现假成功。
- README 说明体检的外部请求、可能费用、隐私边界与手动验收方法；不新增依赖。

## 边界用例（实现时必须想到）

1. 档案没有模型：返回可读的未检测结果，耗时为空且零网络请求。
2. 指定模型不在档案清单：拒绝请求并返回可读校验错误；清单中的模型被上游拒绝时归类为模型不存在。
3. 没有密钥：按协议允许无认证请求时可继续检测；上游认证拒绝应归类为密钥无效。密钥存储缺失 / 异常必须与认证失败区分。
4. 错地址包含 DNS / 连接 / TLS 失败，且不回显异常原文；上游重定向不得携带密钥跟随到其他地址。
5. 上游超时、429 限流、5xx、非 JSON / 畸形响应分别可读；每次用户操作最多发出一个探测请求。
6. 同档案重复点击 / 并行点击：UI 防止重复提交；后端单次调用仍不产生任何配置写入。
7. 四种手动验收场景：正确地址、错误地址、错误 key、清单内但上游不存在的模型，结论各不相同。

## 不做（明确划界）

- 不实现后台定时 / 低频扫描、自动重试、通知或新增频率设置。
- 不保存体检历史，不新增 SQLite 迁移、历史查询 API 或修改工具状态。
- 不修改档案、密钥、工具配置、快照、回滚或审计数据。
- 不发送用户对话内容、不做模型对话、不提供原始上游响应或完整密钥查看。
- 不扩展支持协议或新增依赖；不改 `requirements.md` 的需求边界。
