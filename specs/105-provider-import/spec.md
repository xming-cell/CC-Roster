# 031 — 本地导入供应商

> 来源：`docs/task-plan2.md` 的 105 号规划卡；正式编号 031。
> 依赖：103（供应商列表 / 表单 / 绑定）已完成；ADR-012 已定「版本化 JSON、预览、去重、全或无」。

## 背景与目标

1. 目前只能手工录入供应商，迁移或批量配置成本高。
2. 目标 1：后端新增导入端点，接受带 `schema_version` 的 JSON，逐条校验后全或无写入。
3. 目标 2：前端提供「选文件 → 解析预览 → 处理重复 → 确认导入」对话框；非法项可读说明。
4. 目标 3：导入结果可在供应商页继续编辑与绑定，不自动激活、不写工具配置。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0。
- 文件必须带 `schema_version`；未知版本给出明确错误，不做猜测性兼容。
- 预览区分「新增 / 重复 / 非法」，并显示每条的判断依据。
- 去重键为「名称 + 协议 + 接口地址」；重复项支持跳过或覆盖，默认跳过。
- 写入全或无：任何一条非法或写入失败都不产生部分供应商。
- 导入后在供应商页可见，绑定 `active=false`，不写工具配置文件。
- 错误覆盖：空文件、坏 JSON、缺字段、重复、超长、未知版本、顶层不是对象。
- 设计稿已在 Penpot 出稿、导出快照并获用户确认（记录在 `docs/task-board.md`）。
- 测试与手动验收表完成并回填。

## 边界用例（实现时必须想到）

1. 空文件 / 只有 BOM / 坏 JSON / 顶层是数组 → 可读错误，不进入预览。
2. `schema_version` 缺失、非整数、过高 → 明确拒绝，提示支持范围。
3. 单条缺名称 / 协议 / 地址 / 模型为空 / 密钥引用非法 → 标为非法，整批不写入。
4. 同批次内部重复、与已有供应商重复 → 预览中分别标出，跳过或覆盖行为确定。
5. 超长名称 / 地址 / 模型列表 → 409 / 422 可读，不部分写入。
6. 重复提交导入 → 不产生重复供应商。

## 不做（明确划界）

- 不做从工具现有配置反向导入（ADR-012 后续增强）。
- 不支持 CSV / YAML / 远程 URL 导入。
- 不导入会话、用量、审计等供应商以外数据。
- 不自动激活、不写工具配置（属于 104）。
