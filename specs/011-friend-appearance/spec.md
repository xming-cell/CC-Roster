# 011 — 每个 AI 独立外观

> 输入：`docs/task-plan.md` 的 011 卡；`docs/requirements.md` F-09 / N-1；`docs/decisions.md` ADR-002 / ADR-007；005 好友列表与 `frontend/src/styles/tokens.css` 的外观 token。
> 依赖：005 已完成；010 搜索与筛选已完成。外观按工具 ID 归属，不随档案切换而改变。
> 本卡只实现每个好友的主题色、聊天背景与气泡样式；不改变工具配置、档案、会话数据或应用全局主题。

## 开卡决策

1. **稳定身份色**：遵循 ADR-002，主色按稳定 `tool_id` 确定性生成；供应商 / 模型家族仅影响次级强调色，不能让同一工具切换档案后主色跳变。未知工具也必须得到有效外观，不依赖随机数或运行时顺序。
2. **默认即完成**：未保存覆盖时由前端按工具身份、供应商和模型推导完整默认外观；外观不是好友实体，不把默认结果持久化。主题 token 同时提供明 / 暗环境下可读的前景与背景配对，但不新增应用级主题切换。
3. **覆盖与恢复**：用户可为单个工具覆盖强调色、聊天背景色并选择气泡预设；提供明确的「恢复默认」操作。其他工具外观不受影响。
4. **独立可重建存储**：仅把显式覆盖保存到应用数据目录下独立的 `appearances.json`，以工具 ID 为键；通过版本化 schema、原子写和文件锁保护。删除该文件只会清除外观覆盖并恢复默认，不得影响档案、工具配置、快照或审计数据。
5. **窄范围应用**：外观应用于好友列表项 / 头像、当前好友详情与会话时间线预留区；不重做 005 布局、不改 `/tools` 与 `/profiles` 页面，不要求本卡实现会话回放或对话。
6. **无新依赖**：复用现有 Pydantic、原子 JSON 写入、文件锁和前端控件；不改依赖清单或锁文件。

## 背景与目标

1. F-09 要求每个 AI 好友有独立的主题色、聊天背景和气泡样式，默认自动生成且无需用户配置。
2. 同时出现至少五个好友时，用户应能不读名字、仅凭清晰且稳定的视觉差异区分；颜色必须可读，不能牺牲前景 / 背景对比。
3. 手动覆盖是可选偏好，不应成为好友可用性的前提，也不得改变配置真相源或随供应商档案切换而丢失身份。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0，完整输出记录在本卡 `tasks.md`。
- 默认外观对同一 `tool_id` 可重复、跨加载稳定；工具 ID 不同的默认主色不依赖列表顺序。供应商 / 模型只影响次级强调样式，不覆盖身份主色。
- 至少五个代表性工具 ID 的默认外观视觉上可区分；测试量化主色间差异，并验证明 / 暗环境下文字与关键交互颜色的对比度达到 WCAG AA（正文至少 4.5:1，非文字 UI 至少 3:1）。
- 外观覆盖 API 使用显式 Pydantic 输入 / 输出；支持读取全部覆盖、按工具 ID 保存覆盖、恢复该工具默认外观。非法颜色 / 样式被 422 拒绝，未知字段不被静默保存。
- `appearances.json` 缺失表示空覆盖；损坏或不支持的 schema 版本返回可读错误且不覆盖原文件。并发更新不会丢失其他工具覆盖；写失败不返回成功。
- 删除外观存储文件 / 重启后，所有工具均恢复确定性默认外观；档案、工具配置、快照、审计和数据库内容不因外观读写变化。
- 主界面好友条目和选中好友详情使用对应外观；覆盖只影响目标工具，页面刷新后保持，恢复默认后立即还原；搜索 / 筛选、排序、选中 ID 和详情行为保持不变。
- 外观编辑支持键盘操作和可读 label；默认与覆盖色在明 / 暗环境均有足够对比，窄屏不产生横向溢出；保存 / 恢复失败必须明确展示且不得伪装成功。
- README 说明默认推导、覆盖 / 恢复方式、`appearances.json` 可重建边界；不新增依赖。

## 边界用例（实现时必须想到）

1. 空好友列表、未配置工具、解析失败工具、缺供应商 / 模型与未知工具 ID 都有稳定可用的默认外观。
2. 工具列表重排、重新加载、档案切换或应用重启不得改变同一工具默认主色或其已保存覆盖。
3. 五个以上代表性工具 ID 的颜色差异须量化；极浅 / 极深颜色在明 / 暗环境都不能使文字、焦点环或选中态不可读。
4. 外观覆盖只作用于一个工具；覆盖一项不误清其他覆盖；恢复默认不删除其他工具设置，重复恢复幂等。
5. 颜色格式、超长工具 ID、非法 / 未知气泡预设、未知请求字段和空 body 均返回清楚的校验错误，不写入文件。
6. `appearances.json` 缺失、空文件、坏 JSON、结构错误、未知 schema 版本、只读目录与文件锁超时均不得静默成功或破坏旧数据。
7. 并发更新不同工具外观时两边都保留；同一工具重复保存同一覆盖结果幂等。
8. 搜索结果变化或当前好友被筛出时，外观不会串到其他好友；筛选清除后原工具仍显示原主题。
9. 保存 / 恢复失败时显示可操作错误；用户取消编辑不应改变已应用外观。
10. 键盘可达编辑器、焦点可见、320px 窄屏以及系统明 / 暗偏好下均可读。

## 不做（明确划界）

- 不改变 ADR-002 的好友身份：不按档案或项目目录拆好友，不因更换供应商 / 模型重置主色。
- 不把外观或配置写入被管理工具的配置文件、档案、会话历史、快照或审计记录。
- 不新增 SQLite 业务表 / 迁移；不把默认外观写盘；不实现云同步、账号体系或跨设备同步。
- 不新增应用级深色模式、全局配色设置、主题市场、动画 / 音效、头像上传或图像生成。
- 不实现会话回放 / 对话气泡内容；仅提供未来可复用的聊天背景与气泡 CSS token。
- 不修改 `/tools`、`/profiles` 的既有行为，不新增依赖或 UI 库。
