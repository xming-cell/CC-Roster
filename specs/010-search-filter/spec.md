# 010 — 搜索与筛选

> 输入：`docs/task-plan.md` 的 010 卡；`docs/requirements.md` F-12；005 的好友列表与排序行为。
> 依赖：005 已完成。功能挂在 `/` 主界面；`/tools` 过渡页面保持不变。
> 本卡只筛选已发现的工具，不新增持久化索引，也不改变工具配置或发现状态。

## 开卡决策

1. **后端兼容筛选参数**：`GET /api/tools` 增加可选 `name`、`provider`、`model`、`status` 查询参数。文本参数分别按去空白后的大小写不敏感子串匹配；多个非空参数按 AND 组合；空值忽略；状态精确匹配 `ok` / `unconfigured` / `error`。
2. **前端内存即时过滤**：`/` 复用已加载的列表，不因输入或切换状态重新请求 API。搜索词按去空白、大小写不敏感的子串，在名称 / 供应商 / 模型三字段中任一匹配即显示；状态筛选与搜索词按 AND 组合。搜索输入防抖 200ms，状态切换即时生效。
3. **不建索引**：后端按请求发现工具后在内存中过滤；前端对当前列表作纯内存过滤。无需 SQLite 迁移、新表或依赖。
4. **保留列表语义**：过滤结果沿用 005 的原排序；过滤不改变工具数据、选中 ID 或详情。被过滤隐藏的已选工具仍显示详情，清除筛选后列表项恢复选中。
5. **只改主界面**：不改 `/tools` 过渡页面、不改变适配器发现 / 读取行为；空结果文案区分「没有安装工具」与「没有匹配项」。

## 背景与目标

1. F-12 要求用户可按名称、供应商、模型与状态筛选，并即时看到结果。
2. 工具列表已有名称、供应商、模型、状态和稳定排序；本卡在此基础上加入组合筛选，不引入第二份持久状态。
3. 页面筛选时不丢失所选工具详情，不清空后端完整列表，且空结果可恢复。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0，完整输出记录在本卡 `tasks.md`。
- `GET /api/tools` 接受可选 `name` / `provider` / `model` / `status`：
  - 文本条件去除首尾空白后作大小写不敏感子串匹配；空字符串与纯空白等同于未提供。
  - 同时提供多个条件时按 AND 过滤；缺少对应值的条目不匹配该文本条件；状态为精确匹配。
  - 非法状态返回 422；不带筛选参数时响应内容、warnings 与原有顺序不变。
- 主界面搜索框在名称、供应商、模型任一字段中匹配关键词，状态 chips 可单选并与关键词组合；搜索输入在停止输入 200ms 后反馈，状态切换立即反馈。
- 筛选只作用于已加载列表，不触发额外网络请求或持久化；原有排序稳定，选中 ID 与详情不会因临时筛掉条目而重置。
- 无匹配结果时显示明确文案及清除筛选入口；真正没有已发现工具时仍显示 005 的安装引导。
- 至少 120 条工具的 API 与 UI 用例覆盖筛选和空结果；性能验证记录内存过滤结果，不引入持久化索引。
- README 说明主界面搜索 / 筛选行为与 API 参数；不新增依赖。

## 边界用例（实现时必须想到）

1. 查询参数缺省、空字符串、纯空白与前后空白；不得把空值当成空字段匹配。
2. 名称 / 供应商 / 模型大小写不同仍匹配；缺失供应商或模型不匹配相应非空条件。
3. 多个文本参数与状态同时出现时组合结果明确；无匹配返回空列表而不是错误。
4. 未知状态返回 422；无过滤参数时旧调用方得到原结果。
5. 120+ 条工具、空列表、只有一个匹配项与零匹配项。
6. 已选工具被筛掉时详情保留；清除条件后列表选中态恢复；用户选择其他可见工具后详情正常切换。
7. 连续快速输入只展示最新关键词结果；防抖期间状态切换不会丢失当前搜索词。
8. 清除筛选后恢复完整列表及原排序；过滤不触发重新扫描或网络请求。

## 不做（明确划界）

- 不新增 SQLite 索引 / 缓存表或任何跨重启搜索状态。
- 不修改工具适配器、文件发现 / 解析、配置、档案、快照或审计行为。
- 不改 `/tools` 过渡页面与其现有测试行为。
- 不实现多选状态、模糊排序、搜索历史或跨字段高级查询语法。
- 不做虚拟滚动或额外搜索依赖。
