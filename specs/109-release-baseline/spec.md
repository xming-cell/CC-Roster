# 035 — V2 验收与发布基线

> 来源：`docs/task-plan2.md` 的 109 号规划卡；正式编号 035。
> 依赖：104–108 全部完成。
> 性质：验收卡。只修验收与文档层面的问题；业务缺陷回各自卡片修。

## 背景与目标

1. 确认新前端与保留后端形成完整闭环，达到可发布状态。
2. 目标 1：跑通自动化回归与三平台 CI，确认没有回退。
3. 目标 2：真人 E2E 覆盖主流程，记录真实结果，不用组件测试代替。
4. 目标 3：性能、跨平台、文档与交接收口，明确列出延后 / 不做项（D-16）。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0，完整输出贴入 `tasks.md`。
- 三平台 CI（ubuntu / macOS / Windows）通过。
- 手动 E2E 场景表逐项真实执行并填写：首次查看工具、空列表、异常工具、添加供应商、同一工具绑定两个供应商、切换并回滚、新建会话、流式对话、中断、历史回放、审计、用量、设置。
- 性能：主界面可用、工具扫描不阻塞、上百会话不卡顿；记录实测数字与机器环境。
- 无空壳导航、无未接入入口、无假成功提示。
- `PROGRESS.md`、`README.md`、`docs/task-board.md` 与各卡交接更新。
- 明确列出延后 / 不做的旧功能（对应 D-16 / ADR-014）。

## 范围

```scope
docs/**
README.md
scripts/**
```

## 边界用例（实现时必须想到）

1. 某平台 CI 因环境差异失败 → 记录原始日志与定位结论，不靠重跑碰运气。
2. 手动 E2E 发现缺陷 → 记录复现步骤，回对应卡片开修复，不在本卡顺手改业务代码。
3. 性能不达标 → 给出瓶颈与后续卡建议，不用「测试绿」掩盖。
4. 延后项必须写清原因与替代路径，不能只写「以后再说」。

## 不做（明确划界）

- 不在本卡实现新功能或改业务行为。
- 不引入新的打包 / 发布平台；是否打包桌面壳按 D-16 结论执行。
- 不用自动化测试替代手动 E2E。
