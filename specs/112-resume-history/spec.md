# 038 — 从历史会话继续

> 来源：用户 2026-11-17 追加需求（对应规划 112）。
> 2026-11-18 用户修订交互：否决「继续这段对话」按钮式方案，改为主流 harness 的「历史页直接输入」。
> 依赖：107（历史回放）已完成；本机已核实 Claude `--resume` 与 Codex `exec resume`。

## 背景与目标

1. 历史目前只能只读回放，用户希望能接着上次对话继续问。
2. 目标 1：进入某段历史会话后，时间线底部直接出现输入框；不输入就是只读，输入并发送才表示继续。
3. 目标 2：发送时创建一个新的应用会话，记录 `resume_from_tool_id` / `resume_from_session_id`，并立即把首条消息发给原工具。
4. 目标 3：只有声明支持 resume 的工具显示输入框；不支持的工具有明确只读说明。原历史文件不被本应用修改。

## 交互契约（本轮核心）

- 打开历史会话 = 只读回放。**不出现**「继续这段对话」按钮，**不出现**「只读 / 继续」二选一，**不弹**二次确认框。
- 支持 resume 且上下文可用时，历史时间线底部固定一个与对话页一致的输入框，并在输入框上方显示当前模型 / 思考强度选择器；提示文案表达「输入消息即可从这段历史继续」。
- 输入为空或只有空白：发送按钮禁用；不发送不创建任何应用会话，也不改变历史文件。
- 首次有效发送：
  1. 使用当前历史会话的 `tool_id`、历史摘要中的 `project_path`、当前工具 active 供应商创建新 `ChatSession`；
  2. 请求携带 `resume_from_tool_id` / `resume_from_session_id`；
  3. 创建成功后立即发送这条消息，并切到对话视图；
  4. 在对话视图显示「已从这段历史继续」成功提示。
- 同一段历史重复发送：每次发送都新建一个续聊会话，标题为「续 · 原标题」，不复用上一次续聊，避免两个分支混在一起。
- 续聊期间历史侧栏不自动刷新，避免用户正在阅读的位置跳动。
- 不支持 resume 的工具：不渲染输入框，显示「当前工具不支持从历史继续」的只读说明。
- 支持 resume 但没有可用 active 供应商 / 密钥 / 项目目录：输入框禁用并说明原因；不允许先创建半截会话。
- 原历史仍然只读；发送动作只写本应用的新会话。若工具自身在 resume 时追加原会话文件，文档需说明这是工具行为，不是本应用改写。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0。
- `ToolCapabilities` 增加 `resume`（或等价字段）：Claude / Codex 为 true，其它为 false。
- Claude 命令追加 `--resume <session-id>`；Codex 使用 `exec resume <session-id>`（均已本机核实）。
- `ChatSession` 记录 `resume_from_tool_id` / `resume_from_session_id`；续聊命令携带恢复参数。
- 历史时间线：Claude / Codex 显示底部输入框与模型 / 强度选择器；其它工具不显示输入框并说明原因。
- 空输入 / 仅空白不创建会话；有效发送创建带 resume 字段的新会话，并切换到对话视图、显示成功提示。
- 创建失败（原会话不存在、跨工具、工具不支持、上下文不可用）时不发送消息、不产生半截会话，错误可读。
- 新会话的项目目录来自历史摘要；项目目录为空或不存在时禁止发送并说明原因，不回退到该工具最近目录。
- 历史输入框上方的模型 / 强度选择器默认使用当前工具 active 供应商的默认模型与当前强度；不解析原历史文件。
- 测试覆盖：能力表、命令映射、输入框可见性、模型 / 强度默认值、空输入、创建会话字段、发送时命令带 resume、错误路径、原历史文件 hash 不变。
- 清理本卡后端测试里被禁用的类型忽略注释（`# type: ignore[attr-defined]`），改用显式 fake / stub，确保 `guard forbidden` 通过。
- 设计稿重出并经用户确认：历史会话输入框空态、输入态、续聊成功、上下文不可用、工具不支持。

## 边界用例（实现时必须想到）

1. 会话 id 含特殊字符 → 只作为参数传递，不拼 shell 字符串。
2. 原会话已被删除 / 工具版本不支持 resume → 可读错误，不产生半截会话。
3. 同一历史重复发送 → 每次新建续聊会话，标题加「续」；不覆盖旧续聊。
4. 历史详情仍在加载 / 读取失败 → 不显示可发送输入框，避免对空上下文发送。
5. 项目目录为空、已删除或不是目录 → 禁止发送并说明原因，不静默回退。
6. 没有 active 供应商 / 密钥缺失 / 工具未安装 → 输入框禁用并说明原因。
7. 切换历史会话时已有草稿 → 草稿不得带到另一段历史。
8. 长消息 / 多行消息 → Enter 发送、Shift+Enter 换行；超长由后端校验并回显可读错误。

## 已确认决策（2026-11-18）

1. **模型 / 强度来源**：采用方案 A。历史输入框上方显示模型 / 强度选择器，默认使用当前工具 active 供应商的默认模型与当前强度（通常为空）；不解析原历史文件。
2. **项目目录回退**：历史 `project_path` 为空、已删除或不是目录时，禁止发送并说明原因，不回退到该工具最近会话目录。
3. **不支持工具的表现**：完全不渲染输入框，只显示「当前工具不支持从历史继续」的只读说明（与 107 的 J-7 一致），不显示禁用输入框。

## 不做（明确划界）

- 不做「分叉 / fork」语义的 UI（Codex 支持 fork，但本期只做 resume）。
- 不做跨工具续聊（Claude 会话不能用 Codex 恢复）。
- 不改历史回放的只读默认与 hash 校验。
- 不保留旧的「继续这段对话」按钮 / 模式切换 / 二次确认交互。
