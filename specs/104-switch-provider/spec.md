# 030 — 切换供应商：预览、应用、回滚

> 来源：`docs/task-plan2.md` 的 104 号规划卡；正式编号 030。
> 依赖：103（`551eed2`）已完成；后端已有 switch preview/apply、snapshot、rollback，本卡只做增量与入口。

## 背景与目标

1. 供应商页目前只能管理配置，不能把某个供应商真正写进工具配置；切换必须是显式、可预览、可撤销的写操作。
2. 目标 1：后端补齐审计 action，覆盖 apply / rollback 与供应商增删改、复制、绑定激活；不记录读取，不含密钥与文件原文。
3. 目标 2：前端完成「预览 → 确认应用 → 结果 / 快照 → 回滚」闭环；任何确认前磁盘零变化。
4. 目标 3：冲突（外部改动、只读、无权限）与失败都有可读说明，以及取消 / 重新检查路径。

## 验收标准（DoD）

- `uv run python scripts/check.py` 退出码 0。
- 预览展示目标工具、目标供应商、逐字段 before/after、涉及文件、重启要求与 blockers；取消预览后磁盘零变化。
- 应用成功显示结果、快照入口与操作记录入口；失败自动还原并明确告知已还原。
- 重复提交被锁定；重复点击或并发提交只产生一次写入。
- 回滚入口可达；回滚后目标文件与快照逐字节一致。
- 审计覆盖 apply / rollback 与供应商增删改 / 复制 / 激活，记录可读且无密钥、无文件原文、无完整请求体。
- 前端设计稿已在 Penpot 出稿、导出快照并获用户确认（记录在 `docs/task-board.md`）。
- 组件测试与手动验收表完成并回填。

## 边界用例（实现时必须想到）

1. 预览后目标文件被外部修改 → 应用返回冲突，不写入，提示重新检查。
2. 目标文件只读 / 目录无权限 → 可读错误，不产生半写状态。
3. 同一预览重复应用 → 第二次被拒绝或幂等返回，不重复写。
4. 快照不存在 / 损坏 → 回滚失败可读提示，磁盘不变。
5. 无绑定、无 active、工具未安装 → 入口禁用并说明原因，不显示可点按钮。
6. diff 为空、仅顺序变化、超长字段值 → 展示不撑破布局，完整值可查看。
7. 应用过程中网络断开 → 前端不显示假成功；重新进入时以服务端状态为准。

- 不改写引擎、快照内核与脱敏语义；只做增量 action 与入口。
- 不做搜索 / 筛选（ADR-014）。
- 不在本卡做 105 导入、106 对话、108 三个信息页。
